# DXA-QC — контроль качества денситометрии (DXA)

Локальный сервис, который по DICOM-исследованию денситометрии поясничного отдела позвоночника
и проксимального отдела бедра определяет, качественное ли изображение, и если нет — какое
нарушение из утверждённого списка обнаружено, и объясняет почему (число, порог, картинка).

Подробный отчёт о том, что сделано, как и почему, — [REPORT.md](REPORT.md).

## Возможности

| Область | Нарушение (метка организатора) | Метод | AUC (честная CV) |
|---|---|---|---|
| Позвоночник | Не выравнена ось позвоночника | правило ТЗ: наклон > 5° | 0.85 |
| Позвоночник | Некорректная укладка | правило ТЗ: не видны гребни подвздошных костей | 0.90 |
| Позвоночник | Присутствуют посторонние предметы | детектор тонких ярких линий (порог по обучению) | 0.95 |
| Бедро | Некорректная укладка | ротация (малый вертел + офсет головки + SigLIP) и видимость седалищной кости | 0.83 |
| Бедро | Некорректная область интереса | правило ТЗ: < 3 см ниже малого вертела | 0.81 |
| Всё | Качественное / есть нарушение | ИЛИ по критериям; `quality_prob` — AUC 0.80 | 0.82 |

* пакетная обработка каталога или zip (в т. ч. вложенного), группировка по `StudyInstanceUID`;
* таблица результатов `.xlsx` + `.csv` в формате ТЗ п. 2.5, одна строка на файл изображения;
* дополнительные серии: PNG и DICOM Secondary Capture с разметкой, DICOM SR с текстом заключения;
* HTTP API и веб-интерфейс для загрузки, просмотра и пакетной обработки;
* ни одно исключение не прерывает пакет: ошибка файла → `processing_status = Failure` и текст в `error`.

## Ограничения

* Обучено и проверено на 100 исследованиях одного аппарата (GE Lunar Prodigy Advance), 252 снимка.
  Пороги в градусах и сантиметрах аппаратно-независимы, но статистическая часть (SigLIP, порог
  детектора предметов) на другом аппарате может потребовать перенастройки.
* Нарушений мало (6–36 на критерий), доверительные интервалы широкие — см. REPORT.md.
* Рамка области интереса GE в выгрузке не нарисована; область интереса бедра строится
  по анатомическим ориентирам, решение принимается по отступу снизу (см. REPORT.md, раздел 4.4).
* Тег `(0040,0303) Exposed Area` в части файлов неверен; размер пикселя принимается только
  в диапазоне 0.4–1.0 мм, иначе 0.6 мм.
* Сервис — помощник контроля качества, не средство диагностики.

  roi.py             ориентиры бедра и область интереса

  features.py        все измерения + признаки SigLIP
  model.py           решение по критериям (пороги, логрегрессия), обучаемые параметры
  pipeline.py        пакетная обработка, группировка, область и сторона, устойчивость к ошибкам
  report.py          доп. серии: PNG, DICOM SC, DICOM SR
  predict.py         командная строка
  api.py, static/    HTTP API и веб-интерфейс
  cv.py              честная кросс-валидация (группы по исследованию, бутстрэп ДИ)

evaluate_final.py    честная оценка системы тем же кодом → out/metrics_final.json

perm_test.py         перестановочный тест (контроль утечек)
vlm_probe.py         эксперимент с локальной VLM (Qwen3-VL-2B) на посторонних предметах
tests/               дымовые тесты (python -m pytest tests -q)
eval_*.py, embed.py, sam_*.py, make_slides.py   исследования и картинки для отчёта/презентации

## Системные требования

| | Минимум | Рекомендуется |
|---|---|---|
| CPU | 4 ядра x86-64 | 8+ ядер |
| ОЗУ | 6 ГБ | 16 ГБ |
| GPU | не нужен | любой CUDA-GPU ≥ 4 ГБ (ускоряет SigLIP в ~20 раз) |
| Диск | 8 ГБ (образ ~6 ГБ) | 15 ГБ |

Скорость на CPU (8 потоков): ~2–4 с на снимок, одно исследование (3 снимка) ~10 с —
с большим запасом до лимита ТЗ в 3 минуты. Загрузка моделей при старте ~15 с.

Зависимости и версии — `requirements.txt` (все зафиксированы), базовый образ
`python:3.10.16-slim-bookworm`, `torch==2.12.0` (CPU или CUDA 12.8).

## Сборка и запуск (Linux / UNIX)

Веса и модель должны лежать в `weights/` и `models/` (в комплекте). Если их нет:

```bash
python scripts/export_siglip.py                 # один раз, нужен интернет или кэш HF
python train.py --data /path/to/НД_для_обучения # ~15 мин на CPU
```

Далее:

```bash
chmod +x run.sh
./run.sh build                                   # или build-gpu
./run.sh predict /path/to/dicom_or.zip ./result  # пакетная обработка
./run.sh api                                     # веб-интерфейс: http://localhost:8000
```

На Windows (Docker Desktop не нужен): Docker Engine в WSL2 Ubuntu —
`sudo apt-get install -y docker.io docker-buildx`, затем те же команды `run.sh` из WSL.
Пути к входу/выходу берите без кириллицы (например `/mnt/c/dxa_in`, `/mnt/c/dxa_out`).
Если за VPN в WSL нет сети — `networkingMode=mirrored` в `%USERPROFILE%\.wslconfig` и `wsl --shutdown`.

Без контейнера (Python 3.10):

```bash
pip install torch==2.12.0 torchvision==0.27.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
python -m dxa.predict --input /data/in --output out/results.xlsx --series out/series
uvicorn dxa.api:app --port 8000
```

## Руководство пользователя (веб-интерфейс)

1. Запустить `./run.sh api` и открыть http://localhost:8000.
2. «Выбрать файлы» — zip-архив или несколько DICOM-файлов; «▶ Обработать».
3. В журнале строки красные — есть нарушение, зелёные — качественное, жёлтые — ошибка чтения.
   «только с нарушениями» — фильтр.
4. Щелчок по строке — снимок с разметкой (красное — нарушение) и заключение с числами и порогами.
5. «Отчёт XLSX / CSV», «Доп. серии (ZIP)» — выгрузка результатов. Ссылка вида `/?job=<id>`
   открывает уже обработанное задание.

## Руководство по развёртыванию

* Сервер Linux с Docker (для GPU — nvidia-container-toolkit). Каталоги `models/` и `weights/`
  входят в комплект; сеть при работе не нужна.
* `./run.sh build` (или `build-gpu`) → `./run.sh api` (порт 8000) либо `./run.sh predict <вход> <выход>`
  для пакетной обработки закрытого набора без интерфейса.
* Задания API хранятся в `/data/jobs` контейнера (переменная `DXA_JOBS`); чтобы сохранять
  их между перезапусками, смонтируйте том: `docker run -v /srv/dxa-jobs:/data/jobs ...`.
* Проверка готовности — `GET /health` (используется HEALTHCHECK образа).

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | веб-интерфейс |
| GET | `/health` | `{"status":"ok"}` — готовность |
| POST | `/api/jobs` | form-data `files`: zip и/или DICOM-файлы → `{"id", "status"}` |
| POST | `/api/jobs/path` | JSON `{"path": "/data/input"}` — обработать каталог на сервере |
| GET | `/api/jobs/{id}` | статус (`running/done/error`), прогресс, строки результата |
| GET | `/api/jobs/{id}/results.xlsx`, `results.csv`, `series.zip` | файлы результата |
| GET | `/api/jobs/{id}/overlay/{path}` | PNG с разметкой |

Пример пакетной обработки через API:

```bash
curl -F files=@study.zip http://localhost:8000/api/jobs          # → {"id":"a1b2..."}
curl http://localhost:8000/api/jobs/a1b2...                       # статус и строки
curl -o results.xlsx http://localhost:8000/api/jobs/a1b2.../results.xlsx
```

## Входные данные

DICOM-файлы (любые имена и вложенность, zip допускается, в т. ч. вложенный; имена в zip из
Windows в cp866 распознаются). Исследование определяется по `StudyInstanceUID`, изображения —
по `SOPInstanceUID`. Одинаковые по пикселям копии обрабатываются один раз (`duplicate_of`).
Область (позвоночник/бедро) — по тегам и имени файла, при их отсутствии — по изображению
(классификатор на SigLIP). Сторона бедра — по тегам/имени (`ЛПОБ`, `ППОБ`, `left`, `right`),
иначе по анатомии (головка и таз медиально).

## Выходные данные

`results.xlsx` и `results.csv` (UTF-8 с BOM), одна строка на файл изображения:

| Колонка | Описание |
|---|---|
| `path_to_study` | путь к файлу |
| `study_uid`, `image_uid` | из DICOM-тегов |
| `anatomical_region` | «Поясничный отдел позвоночника» / «Проксимальный отдел бедра» — без стороны («Разъяснения V2», вопрос 15) |
| `quality_class` | 0 — качественное, 1 — есть нарушение |
| `quality_prob` | вероятность нарушения, [0;1] («Разъяснения V2», вопрос 8): P(хотя бы одно нарушение) по откалиброванным вероятностям критериев. Порог `quality_class` подобран по F1, поэтому класс 1 возможен и при вероятности < 0.5 — для редкого брака оптимальный порог ниже 0.5 |
| `violation_type` | перечень нарушений через «; » (названия как в разметке организатора) |
| `processing_status` | Success / Failure |
| `time_of_processing` | секунды на изображение |
| `details` | объяснение по каждому критерию: измеренное значение и порог |
| `duplicate_of` | если файл — копия другого изображения исследования |
| `error` | текст ошибки при Failure |

`series.zip` (или каталог `series/`): для каждого снимка `*.png`, `*_SC.dcm` (Secondary Capture
с разметкой, новая серия в том же исследовании), `*_SR.dcm` (Basic Text SR с заключением).

## Модель, предобработка, постобработка

* **Предобработка:** чтение `pixel_array` (JPEG/JPEG2000 через pylibjpeg), MONOCHROME1 → 2,
  нормализация по перцентилям 0.5–99.5; размер пикселя — из Exposed Area с проверкой
  правдоподобия; бедро приводится к единой ориентации (медиально справа).
* **Измерения** (без обучения): средняя линия позвоночника и угол по двум крайним участкам;
  доля кости гребней у нижнего края; гессиановый детектор тонких ярких линий; маска бедра,
  головка (карта расстояний), малый вертел (выступ медиального контура), офсет головки,
  область интереса и отступы в см.
* **Обучаемое:** логрегрессия на 16 главных компонентах признаков замороженного SigLIP-so400m
  (бедро), медиана выступа малого вертела у нормы, пороги детектора предметов и оценки
  ротации (максимум F1 на обучающих данных).
* **Постобработка:** флаг по каждому критерию, `quality_class` = ИЛИ флагов области;
  несколько нарушений перечисляются все (мультилейбл).

Обучение — `train.py`; честная оценка — `evaluate_final.py` (вложенная CV, группы по исследованию,
5×5 фолдов, 95% ДИ бутстрэпом по исследованиям). Дообучение на новых данных: положить набор
в формате организатора и выполнить `train.py --data ...`, затем пересобрать образ.

## Известные ошибки и обработка

| Ситуация | Что происходит |
|---|---|
| файл не DICOM / битый | строка с `Failure`, текст в `error`, пакет продолжается |
| DICOM без пикселей (SR, DICOMDIR) | пропускается |
| сжатие, которое не декодируется | `Failure` с сообщением pydicom |
| Exposed Area отсутствует или неверен | размер пикселя 0.6 мм, измерения в мм приблизительны |
| бедро почти не попало в кадр | ориентиры ненадёжны; оценки ротации/области интереса могут быть неверны |
| область не определилась по тегам | решает классификатор по изображению |
| нет GPU | работает на CPU (медленнее) |
